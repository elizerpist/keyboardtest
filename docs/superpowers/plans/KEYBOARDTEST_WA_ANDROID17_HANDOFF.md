## 12. Layers, bounds and ownership

Provider owns the white background and text. WA's AppWidgetHost owns the actual AppWidgetHostView and its widget ID. Its primary default-display frame (`WidgetFrameDelegate.ID == -1`) owns the bounded window and position. Android owns permission grants, binding consent, keyguard and unlock. Flutter owns only the keyboard UI and an unlocked entry to setup. No Flutter engine, preview activity or foreground keyboard activity may be required at wake.

Use the primary frame for the one-item lab preset on this distinct installation. Define the lab frame as the exact primary frame + default display + explicitly enrolled test provider/ID in that frame, with the lab option enabled. Scope first-use and gesture adaptations to this identity. An occupied user-customized primary frame must be preserved. Expose the conflict in setup and allow the user to return to full WA settings. Normal WA editing, other providers and other frames must keep their existing behavior.

Compute a square default frame of **144 dp** per side where it fits, with a 2-column × 2-row WA grid and a single widget spanning 2 columns × 2 rows. This is a specified lab size, not a promise about OEM cell dimensions. A narrow viewport scales down to fit. Use current display metrics, density, insets and cutouts to bound the **entire rectangle**. Preserve accessibility to system controls outside the box. Convert between screen coordinates and the delegate's center-gravity offsets. Use stable screen-space deltas while moving a window, so a continuing motion does not feed the moving frame's local origin back into the next delta. Store geometry in WA's existing frame type/orientation system. Re-clamp after size, rotation or inset changes.
